# Approval Protocol

## Required approval brief
For planning-lane work present:
1. What I found
2. What I propose
3. Frontend changes
4. Backend changes
5. Data/migration changes
6. Contract/integration changes
7. What remains untouched
8. KEEP / REFACTOR / REPLACE / MIGRATE
9. Risks and assumptions
10. Implementation phases
11. Verification plan
12. Explicit approval request

## Do not over-ask
After approval, routine decisions inside scope should not trigger repeated confirmation.

Return for approval only if scope materially changes, destructive risk appears, public contracts must break, auth/tenancy meaning changes, migration risk materially increases, or consequential product behavior cannot be inferred.
