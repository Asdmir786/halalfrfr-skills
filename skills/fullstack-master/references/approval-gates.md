# Approval Gates
No approval normally needed for tiny UI fixes, isolated bugs, behavior-preserving local refactors, or implementation of an already-approved contract.

Approval required before new-app architecture, major cross-layer features, frontend/backend replacement, destructive migrations, auth model changes, public contract breaks, framework migrations, or large refactors with meaningful blast radius.

Approval brief: findings, target, frontend, backend, data, contracts/integrations, KEEP/REFACTOR/REPLACE/MIGRATE, risks, phases, verification, explicit request.
