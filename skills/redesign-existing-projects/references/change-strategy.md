# Redesign Change Strategy

## Small Redesign

For localized problems:

- preserve system
- change component or section
- polish surrounding relationships

## Systemic Redesign

When inconsistency is widespread:

- establish shared tokens
- normalize primitives
- update repeated components
- migrate gradually

## Structural Redesign

When information architecture or major composition is the problem:

- protect behavior
- change structure deliberately
- verify call sites and routing

## Sequence

A useful progression:

baseline
-> direction
-> system
-> structure
-> components
-> responsive
-> polish
-> QA

## Principle

Do not mix unrelated cleanup into the redesign merely because the files are already open.
