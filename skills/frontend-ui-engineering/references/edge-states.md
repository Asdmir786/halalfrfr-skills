# UI Edge States

Production UI should account for the states users can realistically encounter.

## Data

Consider:

- loading
- empty
- partial
- stale
- error
- success

Use only states relevant to the feature.

## Controls

Consider:

- default
- hover
- focus
- active
- selected
- disabled
- loading

## Forms

Consider:

- untouched
- focused
- invalid
- valid
- submitting
- server error
- success

## Lists and Tables

Consider:

- zero results
- filtering with zero matches
- pagination boundaries
- long values
- missing optional values
- large datasets

## Content

Consider:

- long names
- localization expansion
- missing imagery
- unexpected aspect ratios
- user-generated content

## Responsive

Consider:

- narrow width
- long navigation labels
- touch targets
- overflow
- keyboard appearance on mobile
- landscape mobile when relevant

## Principle

Do not create theoretical states endlessly.

Handle realistic states that materially affect the user experience.
