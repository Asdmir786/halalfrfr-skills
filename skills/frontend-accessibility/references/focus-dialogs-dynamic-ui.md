# Focus, Dialogs, and Dynamic UI

## Focus Visibility

Keyboard focus should remain clearly visible.

## Focus Movement

Move focus deliberately when interaction context changes substantially.

Examples may include opening a modal or moving into a newly activated workflow.

## Focus Restoration

When a temporary layer closes, restore focus appropriately when practical.

## Dialog

A dialog should generally have:

- accessible name
- deliberate initial focus
- clear close mechanism
- keyboard behavior
- background interaction control
- focus restoration

Use established primitives where possible.

## Hidden UI

Collapsed or hidden regions should not contain accidentally reachable controls.

## Dynamic Updates

Announce meaningful status changes only when users need that information.

Avoid overly noisy live regions.
