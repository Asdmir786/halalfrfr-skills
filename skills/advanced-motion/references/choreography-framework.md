# Choreography Framework

For substantial animated sequences define the story before defining library calls.

## Trigger

What begins the motion?

Examples:

- page load
- viewport entry
- scroll progression
- click
- state change

## Establish

What should the user understand before transformation begins?

## Focus

Where should attention move?

## Transformation

What visually changes?

## Reveal

What new information becomes visible?

## Resolution

Where does the interface settle?

## Timing Relationships

Decide:

- sequential
- simultaneous
- overlapping
- staggered
- scroll-linked

## Motion Hierarchy

Primary objects may move more prominently.

Supporting elements should not compete for attention.

## Exit

If elements leave, ensure the exit does not leave broken interaction or layout state.

## Test

The sequence should still communicate correctly if watched slowly.

If the narrative is only understandable at one exact animation speed, it may be too fragile.
