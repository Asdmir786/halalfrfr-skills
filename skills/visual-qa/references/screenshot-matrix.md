# Screenshot Matrix

Choose representative viewports based on the project.

## Typical Classes

- narrow mobile
- normal mobile
- tablet or intermediate
- small laptop
- normal desktop
- wide desktop when relevant

Exact pixel sizes should match the product and testing environment.

## Height

Also consider a short viewport when the design uses:

- full-screen heroes
- sticky sections
- pinned motion
- fixed navigation

## Themes

If the changed surface supports multiple themes, inspect each affected theme.

## States

Capture only meaningful states.

Examples:

- menu open
- modal open
- loading
- empty
- error

## Principle

The goal is coverage of layout behavior, not a large screenshot collection.
