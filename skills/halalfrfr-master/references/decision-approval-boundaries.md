# Decision and Approval Boundaries

## Agent decides by default

- routine implementation structure;
- conventional library use already established by the project;
- test placement and ordinary test coverage;
- accessible component mechanics;
- low-risk refactoring needed for the requested change;
- semantic naming and normal validation;
- reversible technical details with no material cost or product effect.

## User approval normally required

- product scope or user-visible behavior changes;
- roles, permissions, retention, or deletion policy;
- payment, pricing, refunds, tax, and financial logic;
- a new paid provider or material operating cost;
- destructive data migration;
- major framework or architecture migration;
- a visual direction with no reliable evidence;
- use of sensitive production data;
- production deployment or irreversible external action when the environment requires confirmation.

## Suggestions

Do not implement unrelated improvements. Put them under a separate `Suggestions not implemented` section so the user can choose later.
